## 🚨 처리해야 할 4가지

### 1. ø28 로는 물이 안 샌다 — **개구를 ø38.1 로 키우고 시계각을 175° 로 옮긴다**

계산은 이렇다 (원래 `src/son/spec/hole_defect_28.json` 에 박혀 있던 것 —
그쪽은 다른 팀원 워크스페이스라 사라질 수 있으므로 여기 옮겨 적는다):

```
실효 통과경 = 개구지름 − 2×PCO − 메시절삭
누수 조건   = 실효 ≥ 2×입자지름
현재 입자(PCO 8.0mm, 입자지름 9.6mm): 실효 11.0mm < 필요 19.2mm  → "leaks": false
```

두 갈래 중 **개구를 키우는 쪽으로 간다.** 입자 설정은 팀이 연산량에 맞춰
조율한 값이라 건드리지 않는다(잘게 하면 입자 수가 2.37배가 된다).

🚨 **그런데 ø38.1 을 바닥(180°)에 그대로 두면 바퀴가 빠진다.** 이 로봇 휠은
폭 12mm 라 궤도가 ±8.5° 로, son 로봇(폭 4mm, ±2.9°)보다 3배 가깝다.

```
ø38.1 개구 반각 = asin(19.05/50) = 22.4°
  시계각 180° → 157.6~202.4°  vs  210° 궤도(201.5~218.5°)  →  0.9° 겹침 ❌
  시계각 175° → 152.6~197.4°  vs  같은 궤도                →  4.1° 여유 ✅
  시계각 170° → 147.6~192.4°                               →  9.1° 여유 ✅
```

→ **`DEFECT_CLOCK=175` 로 옮긴다.** `build_defect_w56.py --dia 38.1 --clock 175`
가 이 간섭을 검산해서 찍으므로 그걸로 확인할 것.
(바닥에서 5° 벗어나므로 중력 누수는 그대로 보인다.)

### 2. contactOffset 이 0.5mm → 20mm 로 뛴다 — **안착·주행을 다시 검증해야 한다**

입자는 GPU 물리 전용인데, GPU 접촉 생성 허용치보다 작은 contactOffset 을 주면
접촉이 아예 안 생겨 **로봇이 배관을 뚫고 떨어진다**(repair_demo 실측 기록).
그래서 물 모드는 0.02 를 바닥으로 깐다.

이 로봇은 휠 여유가 **2mm**(휠 바깥 48mm vs 관벽 50mm)뿐이라 20mm 감지폭이
치수보다 훨씬 크다. repair_demo 에서는 통과한 조합이지만 **이 로봇에서는
처음이다.** `probe_robot.py` 를 GPU/0.02 로 먼저 돌려 12/12 밀착이 유지되는지
볼 것.

### 3. 코스가 2배라 입자도 2배 — 연산량이 관건

repair_demo 코스 0.921m → 여기 **1.771m**. 관 내용적 약 13.9L.
게다가 지금은 카메라 훑기가 20Hz 로 렌더를 굽고 있어 겹친다.

→ **순서를 지킬 것: `--no-vision` 으로 물 물리만 먼저 검증하고, 그 다음에
   카메라를 합친다.** 손잡이는 `RECYCLE_HZ`(기본 15) 와 `ISO_PASSES`(기본 2).

### 4. 양 끝이 열려 있다 — 재투입 구간을 s 기준으로 다시 잡는다

수평 관이라 물이 그냥 흘러나간다. repair_demo 는 나간 입자를 재투입하는데
(`recycle_particles`), 주입 구간이 자기 코스 좌표(`INJECT_Y = (0.300, 0.340)`)로
박혀 있다. 우리는 **진행거리 s 기준**으로 다시 잡아야 한다.
주입은 **결승선보다 상류**여야 물살이 로봇을 때리지 않는다.

## 옮겨 올 값 (repair_demo.py, 검증된 것 — 새로 만들지 말 것)

```python
FLOW_V, FLOW_BLEND        = -0.10, 0.20
W_SPACING, W_PCO          = 0.009, 0.008
W_FLUID_REST              = 0.0048
W_LEVEL_Z, W_R_MAX        = 0.020, 0.045
RECYCLE_HZ, ISO_PASSES    = 15, 2          # 옛 동작은 60 / 8
# 입자-강체 contact 0.004 · rest 0.0025 — 미지정 시 로봇이 입자 위에 부상한다
```

유속 부호: 물은 출구→입구로 흐른다(로봇 진행 반대 = 역류 주행).
우리 코스에서는 **접선의 반대 방향**이므로 `course.project()` 가 주는 `(tx, ty)`
를 뒤집어 쓰면 굽힘에서도 맞는다.

## 착수 순서

1. ✅ `build_defect_w56.py --dia 38.1 --clock 175` 로 STL 재생성 + 간섭 검산
   → 여유 4.07°, 실측 구멍 ø38.087mm. `meshes/` 에 들어가 있다.
2. 🔶 `water_demo.py` 로 **로봇 없이** 물만 확인 — 앞 1m 통과(관 밖 0개).
   전 구간 5m 는 아직. (이 단계는 원래 계획에 없었는데, 로봇을 끼운 채로는
   물 문제와 주행 문제가 섞여서 갈라 놓은 것이다.)
3. ⬜ `probe_robot.py` 를 GPU 물리 · contactOffset 0.02 로 돌려 안착 확인
   — **contactOffset 20mm 가 휠 여유 2mm 를 삼키는지가 관건.** 로봇이
   관을 뚫고 떨어지면 여기서 드러난다.
4. ⬜ `zigzag_demo.py --water --no-vision --glass` 로 로봇+물 (누수 보이는지)
5. ⬜ 카메라 합치기 (`--water --glass` — 단, `--glass` 는 검출 정확도를 6배
   떨어뜨린다는 실측이 있다. README 「카메라 검출」 참조)
